# 栈的选型 & 浏览器的前进/后退用什么结构

## 1. 用数组实现栈 vs 用链表实现栈

| 维度 | 数组实现栈 | 链表（通常双链表/单链表头插）实现栈 |
|------|-----------|--------------------------------------|
| 优点 | 实现简单、缓存局部性好、push/pop/peek 都是 O(1)、无指针额外开销 | 动态大小、无容量上限、头部插入删除 O(1)、无需扩容拷贝 |
| 缺点 | 大小固定（动态扩容需拷贝，代价高）、可能溢出 | 每个节点有指针额外内存、缓存不连续、常数略大 |

结论：能预估容量、追求性能 → 数组栈；容量不可控、频繁伸缩 → 链表栈。

## 2. 浏览器前进 / 后退（前进后退导航）用什么结构

这不是简单的「一个栈」，本质是**历史栈（History Stack / Navigation History）**，常见两种实现：

### 方案 A：两个栈（最经典）

- 维护「后退栈」和「前进栈」两个栈，外加「当前页」。
- **后退**：把当前页压入后退栈，从前进栈弹出上一页作为新当前页（若前进栈空则无历史）。
- **前进**：把当前页压入前进栈，从后退栈弹出作为新当前页。
- **访问新页面**：当前页压入后退栈，清空前进栈（因为新分支使「前进历史」失效）。

### 方案 B：带当前指针的双向链表 / 数组

- 所有访问过的页面用**双向链表**串起来，维护一个「当前节点」指针。
- **后退** = 当前指针向前移动一个节点；**前进** = 向后移动一个节点。
- 在新页面处跳转会截断后续链表（丢弃「前进历史」），严格对应方案 A 清空前进栈。
- 每个节点还带 URL / 标题 / 滚动位置等状态（HTML5 History API 的 `state` 对象）。

### 为什么是栈 / 双向链表，而不是普通数组

- 前进后退需要在历史序列里**前后移动指针**，双向链表 O(1) 移动且无需元素平移；数组移动需 shift，代价高。
- 它和 LRU 缓存是「亲戚」：LRU 用「哈希表 + 双向链表」做 O(1) 访问与淘汰，浏览器历史同样依赖双向链表串接 + 指针移动。

## 3. 一句话记忆

- 单线程顺序处理 → 数组栈够用；需要动态伸缩 → 链表栈。
- 浏览器前进后退 → **历史栈（两栈模型）或带当前指针的双向链表**，核心是「可前后移动的线性历史」，不是裸队列。
