# 哈希冲突解决策略详解

## 核心原理

哈希表通过哈希函数将关键字映射到数组索引，不同关键字可能映射到同一索引，这就是哈希冲突。

## 哈希函数设计原则

1. **均匀性**：关键字均匀分布到各个槽位
2. **高效性**：计算快速
3. **确定性**：相同输入总是产生相同输出

## 常见哈希函数

### 除留余数法
```
h(key) = key % m
```
- m通常取质数，避免冲突聚集

### 乘法哈希法
```
h(key) = floor(m * (key * A mod 1))
```
- A通常取黄金分割比0.618

## 冲突解决策略

### 1. 链地址法（Separate Chaining）

**原理**：每个槽位维护一个链表，冲突的元素挂在链表上。

**示例**：
```
哈希表数组：
[0] → null
[1] → 11 → 21 → 31 → null
[2] → 12 → null
[3] → 13 → 33 → null
[4] → null
```

**优缺点**：
- 优点：简单易实现，动态扩容方便
- 缺点：需要额外指针开销，链表过长时查找变慢

### 2. 开放寻址法（Open Addressing）

**原理**：冲突时在数组中寻找下一个空槽位。

#### 线性探测
```
h_i(key) = (h(key) + i) % m, i=0,1,2,...
```

**示例**：
```
插入11 → h(11)=1 → 位置1
插入21 → h(21)=1 → 冲突 → 位置2
插入31 → h(31)=1 → 冲突 → 位置3
```

**优缺点**：
- 优点：无指针开销，缓存友好
- 缺点：容易产生"聚集"现象

#### 二次探测
```
h_i(key) = (h(key) + c1*i + c2*i²) % m
```

**示例**：
```
h_0(key) = h(key)
h_1(key) = h(key) + 1
h_2(key) = h(key) + 4
h_3(key) = h(key) + 9
```

**优缺点**：
- 优点：减少聚集现象
- 缺点：可能无法探测到所有槽位

#### 双重哈希
```
h_i(key) = (h1(key) + i * h2(key)) % m
```

**示例**：
```
h1(key) = key % 17
h2(key) = 13 - (key % 13)
```

**优缺点**：
- 优点：探测分布均匀，无聚集
- 缺点：计算稍复杂

### 3. 再哈希法（Rehashing）

**原理**：冲突时使用另一个哈希函数计算新位置。

```
h1(key) = key % m1
h2(key) = key % m2
...
```

**优缺点**：
- 优点：避免聚集
- 缺点：需要多个哈希函数

## 负载因子与扩容

### 负载因子
```
load_factor = 元素个数 / 数组大小
```

### 扩容策略
- 链地址法：负载因子通常设为0.75~1.0
- 开放寻址法：负载因子通常设为0.5~0.7

### 扩容步骤
1. 创建更大的数组（通常是原大小的2倍）
2. 重新计算所有元素的哈希值
3. 将元素插入新数组

## 删除操作的特殊性

### 链地址法
直接删除链表节点，简单直观。

### 开放寻址法
不能直接删除（会导致查找中断），需要标记为"已删除"：

```
删除位置3的元素 → 标记为DELETED
插入新元素时 → DELETED位置可以被占用
查找时 → 跳过DELETED位置继续探测
```

## 时间复杂度

| 操作 | 平均情况 | 最坏情况 |
|------|---------|---------|
| 查找 | O(1) | O(n) |
| 插入 | O(1) | O(n) |
| 删除 | O(1) | O(n) |

## 实际应用

### Java HashMap
- 采用链地址法
- 链表长度超过8时转为红黑树
- 默认负载因子0.75

### Python dict
- 采用开放寻址法（伪随机探测）
- 动态扩容

### Redis Hash
- 采用链地址法
- ziplist和dict两种底层实现

## 关键要点

- 链地址法适合频繁增删的场景
- 开放寻址法适合内存敏感、查询频繁的场景
- 负载因子是性能的关键指标
- 良好的哈希函数是减少冲突的基础
