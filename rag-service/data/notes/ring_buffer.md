# 环形缓冲区（Ring Buffer）

## 基本原理

环形缓冲区（Ring Buffer，也叫 Circular Buffer）用一段固定大小的线性内存模拟首尾相接的环形结构，按先进先出（FIFO）原则读写数据。核心优势是无需移动元素即可实现数据消费——写满之后指针回绕到起始位置继续使用，避免了线性缓冲区频繁搬移数据的开销。

## 结构与关键变量

- capacity：固定容量（创建时确定，运行期不扩容）
- head（读指针）：指向下一个待读取的位置
- tail（写指针）：指向下一个待写入的位置
- count 或空满判定：用计数器记录当前有效元素数，或者故意空出一个单元来区分"满"和"空"（head == tail 既可能是空也可能是满）

指针回绕靠取模运算实现：`index = (index + 1) % capacity`。递减时通常先加容量再取模：`index = (index - 1 + capacity) % capacity`，避免负数。

## 满了之后的两种策略

1. 覆盖模式（Overwrite）：新数据直接覆盖最旧的元素（head 指针被迫前移）。适合实时性优先、允许丢旧数据的场景，如音频流、传感器采样、键盘输入缓冲。
2. 阻塞/拒绝模式：写满时阻止写入——要么阻塞等待（阻塞队列语义，生产者挂起直到消费者腾出空间），要么返回错误/抛出异常。适合不允许丢数据的场景，如消息队列、日志缓冲。

## 与线性缓冲区的区别

- 线性缓冲区消费后需要把剩余元素整体前移（O(n)），或者用 memmove；环形缓冲区只需移动 head 指针（O(1)）。
- 环形缓冲区容量固定、不可动态扩容；线性缓冲区可以 realloc 扩容。
- 环形缓冲区的内存布局对 CPU 缓存更友好（连续内存、无碎片）。

## 典型应用

- 操作系统键盘/串口输入缓冲
- 音频实时处理（DMA 双缓冲）
- 生产者-消费者模型的固定容量共享缓冲
- LZ77 压缩算法的滑动窗口
- 高性能日志框架（如 LMAX Disruptor）的无锁环形队列

## 面试要点

- 如何判断空/满：计数器法（count==0 空，count==capacity 满）或空一格法（(tail+1)%capacity==head 为满）
- 无锁实现：单生产者单消费者场景下，head/tail 分别只被一个线程修改，用 memory_order 保证可见性即可去掉锁
- 与 BlockingQueue 的关系：BlockingQueue 是接口语义（满则阻塞、空则阻塞），RingBuffer 是底层数据结构；两者可以组合——用 RingBuffer 做存储 + 条件变量做阻塞
