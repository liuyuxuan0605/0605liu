# 数据结构选型指南：什么场景用什么结构

## 哈希表 vs 平衡树（BST/AVL/红黑树）

| 维度 | 哈希表 | 平衡树 |
|------|--------|--------|
| 查找 | 平均 O(1)，最坏 O(n)/O(log n) | 稳定 O(log n) |
| 有序性 | 无序（不能范围查询） | 有序（支持范围、前驱、后继） |
| 插入/删除 | 平均 O(1) | O(log n) |
| 空间 | 负载因子控制，可能浪费 | 按需分配 |
| 实现复杂度 | 简单（但好的哈希函数不简单） | 复杂（旋转、着色） |

选型：
- 只需精确查找（key → value）：哈希表
- 需要范围查询（WHERE x BETWEEN a AND b）：平衡树
- 需要有序遍历 / 前驱后继：平衡树
- 需要最坏情况保证（实时系统）：平衡树（哈希表最坏不可控）
- 需要去重 + 排序：平衡树（或排序后二分）

## 数组 vs 链表

| 维度 | 数组 | 链表 |
|------|------|------|
| 随机访问 | O(1) | O(n) |
| 头部插入 | O(n)（需搬移） | O(1) |
| 中间插入 | O(n) | O(1)（已知位置） |
| 缓存友好 | 好（连续内存） | 差（指针跳跃） |
| 空间开销 | 无额外 | 每节点多指针 |

选型：
- 频繁随机访问 / 二分查找：数组
- 频繁头部/中间插入删除：链表
- 实现栈：数组（缓存友好）
- 实现队列：循环数组（固定容量）或链表（不确定容量）

## 递归 vs 迭代

| 维度 | 递归 | 迭代 |
|------|------|------|
| 代码简洁度 | 简洁（树/图/分治天然递归） | 可能冗长 |
| 空间 | O(递归深度) 栈帧 | O(1) 或显式栈 |
| 溢出风险 | 深度大时栈溢出 | 无 |
| 性能 | 函数调用开销 | 通常更快 |

选型：
- 树遍历、分治、回溯、DFS：递归（代码清晰）
- 深度可能很大（如链表 10 万节点）：迭代（防栈溢出）
- 尾递归：理论上可优化为迭代，但 Java/Python 不做尾递归优化，C++ 编译器可能优化

用栈模拟递归的通用方法：
1. 把函数参数和"返回地址"压入显式栈
2. 循环弹栈 → 执行 → 把子问题压栈
3. 本质是把系统调用栈搬到堆上（不受栈大小限制）

## 经典场景选型

- 消息队列 / 任务队列：阻塞队列（链表 + 条件变量）或 RingBuffer（固定容量高性能）
- 操作系统任务调度：优先队列（按优先级/时间片调度）
- 浏览器前进后退：两个栈
- 表达式求值：操作数栈 + 运算符栈
- 最短路径：优先队列（Dijkstra）
- 连通性 / 等价类：并查集
- 滑动窗口最值：单调队列（双端队列）
- LRU 缓存：哈希表 + 双向链表
- 自动补全 / 前缀匹配：Trie（前缀树）
- 区间查询 / 更新：线段树 / 树状数组

## 面试回答模板

"选数据结构先看三个问题：① 操作模式（随机访问还是顺序？插入多还是查询多？）② 约束（容量固定还是动态？单线程还是并发？）③ 性能要求（均摊够用还是要最坏保证？）。比如消息队列：容量固定选 RingBuffer，容量不定选链表队列，多线程选 BlockingQueue。"
