# 堆与 Top-K 问题

## 堆的本质

堆（Heap）是一棵完全二叉树，满足堆序性质：最小堆中每个节点 ≤ 其孩子，最大堆中每个节点 ≥ 其孩子。通常用数组存储（下标 i 的左孩子 2i+1，右孩子 2i+2，父节点 (i-1)/2）。

核心操作：
- 插入（sift up）：新元素放末尾，与父节点比较上浮，O(log n)
- 删除堆顶（sift down / heapify）：末尾元素替换堆顶，与较小孩子比较下沉，O(log n)
- 建堆（heapify 整个数组）：从最后一个非叶节点开始逐个 sift down，O(n)（不是 O(n log n)）

## 优先队列 = 堆

优先队列（Priority Queue）是一种接口语义：每次取出优先级最高（或最低）的元素。底层实现通常就是堆。

与普通队列的区别：
- 普通队列：FIFO，先入先出
- 优先队列：按优先级出队，与入队顺序无关

Java 的 PriorityQueue、C++ 的 priority_queue 底层都是二叉堆。

## Top-K 问题

"从 n 个元素中找出最大/最小的 k 个"是堆最经典的面试题。

### 方法一：小顶堆（求最大的 k 个）

维护一个大小为 k 的小顶堆：
1. 前 k 个元素直接入堆
2. 从第 k+1 个开始，若当前元素 > 堆顶（k 个里最小的），则替换堆顶并 sift down
3. 遍历完后堆里就是最大的 k 个

时间 O(n log k)，空间 O(k)。适合海量数据（数据不能全部放入内存时，只需维护 k 大小的堆）。

### 方法二：快速选择（QuickSelect）

基于快排 partition 的思想：
1. 随机选 pivot 做 partition
2. 若 pivot 位置恰好是第 k 大，直接返回
3. 否则在对应半区递归

平均 O(n)，最坏 O(n²)（随机化 pivot 可避免）。不需要额外空间，但会修改原数组。

### 方法三：排序

直接排序取前 k 个，O(n log n)。简单但不够优。

### 选型

- 数据量小 / 一次性：排序最简单
- 数据量大 / 流式数据（实时 Top-K）：小顶堆（O(n log k)，只需 O(k) 内存）
- 需要精确第 k 大且允许修改数组：QuickSelect（平均 O(n)）

## 面试高频问题

- 建堆为什么是 O(n) 而不是 O(n log n)：大部分节点在底层（高度小），sift down 代价低；数学求和 Σ(n/2^(h+1))·h = O(n)
- 堆排序为什么不稳定：sift down 过程中相等元素可能被交换到对方前面
- 堆的 sift up 和 AVL 的左旋有什么不同：sift up 是父子交换（维护堆序），AVL 旋转是改变树的拓扑结构（维护平衡因子）；堆不关心左右子树高度差，AVL 不关心父子大小关系
- 合并 k 个有序链表：用大小为 k 的小顶堆，每次取堆顶（当前最小）并把该链表的下一个节点入堆，O(N log k)
- 数据流中位数：两个堆（大顶堆存较小半 + 小顶堆存较大半），堆顶即中位数
