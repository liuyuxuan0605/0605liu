# 图的存储：邻接表 vs 邻接矩阵

## 邻接矩阵（Adjacency Matrix）

用一个 V×V 的二维数组 matrix[i][j] 表示顶点 i 到顶点 j 是否有边（无权图存 0/1，带权图存权值）。

优点：
- 判断两点之间是否有边：O(1)，直接访问 matrix[i][j]
- 实现简单，适合稠密图
- 方便做矩阵运算（如传递闭包 Floyd-Warshall）

缺点：
- 空间 O(V²)：即使只有很少的边，也要开 V² 的数组
- 遍历某顶点的所有邻居：O(V)，需要扫描整行
- 不适合稀疏图（边数远小于 V² 时大量空间浪费）

## 邻接表（Adjacency List）

每个顶点维护一个链表/数组，存储它的所有邻居（带权图则存 (邻居, 权值) 对）。

优点：
- 空间 O(V + E)：只存实际存在的边
- 遍历某顶点的所有邻居：O(degree)，高效
- 适合稀疏图（大多数实际图都是稀疏的）

缺点：
- 判断两点之间是否有边：O(degree)，需要遍历链表
- 删除边需要链表操作（或用 HashSet 优化）

## 选型对比

| 维度 | 邻接矩阵 | 邻接表 |
|------|----------|--------|
| 空间 | O(V²) | O(V + E) |
| 判断边存在 | O(1) | O(degree) |
| 遍历邻居 | O(V) | O(degree) |
| 适合图类型 | 稠密图（E ≈ V²） | 稀疏图（E ≈ V） |
| 典型应用 | Floyd、传递闭包、小图 | BFS/DFS/Dijkstra/Prim |

经验法则：E < V² / 4 时用邻接表，否则用邻接矩阵。实际工程中绝大多数图是稀疏的，默认用邻接表。

## 其他存储方式

- 边列表（Edge List）：只存所有边的 (u, v, w) 三元组。Kruskal 算法用这种（需要按边权排序）。不支持快速查邻居。
- 前向星（Forward Star）：用数组模拟邻接表（head[] + to[] + next[] + weight[]），C++ 竞赛常用，缓存友好。
- 压缩稀疏行（CSR）：科学计算中稀疏矩阵的标准格式。

## 面试高频问题

- 稀疏图和稠密图怎么区分：E 接近 V 是稀疏，E 接近 V² 是稠密
- BFS/DFS 用哪种存储：邻接表（遍历邻居高效）
- Dijkstra 用哪种存储：邻接表 + 优先队列（O((V+E)logV)）；稠密图也可邻接矩阵 + 数组扫描（O(V²)）
- 如何判断图有没有环：有向图用 DFS 检测后向边（递归栈中再次遇到当前路径的节点）；无向图用并查集（加边前检查两端是否已连通）
- 有向图 vs 无向图的邻接矩阵：有向图矩阵不对称，无向图矩阵对称（可只存上三角省空间）
