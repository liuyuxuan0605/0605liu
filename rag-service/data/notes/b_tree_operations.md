# B树操作详解

## 核心原理

B树是一种平衡的多路搜索树，主要用于数据库和文件系统。B树的阶数（order）决定了每个节点最多包含的关键字数。

## B树特性

设B树阶数为m：
1. 根节点最少1个关键字，最多m-1个关键字
2. 非根节点最少⌈m/2⌉-1个关键字，最多m-1个关键字
3. 每个节点的子节点数 = 关键字数 + 1
4. 所有叶子节点在同一层
5. 关键字有序排列，子树关键字也有序

## 插入操作

### 插入步骤

1. **定位叶子节点**：从根节点开始，根据关键字大小找到目标叶子节点
2. **检查节点空间**：
   - 若节点未满（关键字数 < m-1），直接插入并保持有序
   - 若节点已满，执行分裂

### 节点分裂

**分裂条件**：节点关键字数 = m（超过上限）

**分裂步骤**：
1. 取中间关键字作为新父节点的关键字
2. 中间关键字左侧的关键字留在原节点
3. 中间关键字右侧的关键字形成新节点
4. 新节点成为父节点的子节点
5. 如果父节点也满了，递归分裂

**示例**（阶数m=3）：
```
分裂前节点（已满）：[10, 20, 30]

分裂后：
原节点：[10]
新节点：[30]
中间关键字20上升到父节点
```

### 根节点分裂

根节点分裂时，创建新根节点：
```
原根：[10, 20, 30]

分裂后：
新根：[20]
左子：[10]
右子：[30]
```

## 删除操作

### 删除步骤

1. **定位关键字**：找到包含目标关键字的节点
2. **删除关键字**：
   - 如果是叶子节点，直接删除
   - 如果是内部节点，用前驱或后继替换后删除

### 下溢处理

**下溢条件**：删除后关键字数 < ⌈m/2⌉-1

**处理方式**：

#### 方式1：向兄弟节点借关键字

从相邻兄弟节点借一个关键字：
```
节点A（下溢）：[10]
兄弟节点B：[30, 40]
父节点：[20]

借关键字后：
节点A：[10, 20]
兄弟节点B：[30, 40]
父节点：[30]
```

#### 方式2：与兄弟节点合并

如果兄弟节点也没有多余关键字，合并两个节点：
```
节点A（下溢）：[10]
兄弟节点B（最小）：[20]
父节点：[15]

合并后：
新节点：[10, 15, 20]
父节点：（删除15，可能下溢）
```

### 删除示例

```
B树（m=3）：
        [20]
       /    \
    [10]    [30, 40]

删除10：
- 叶子节点直接删除
- 节点[10]下溢（0 < 1）
- 向兄弟[30, 40]借关键字
- 父节点20下移，兄弟30上移

结果：
        [30]
       /    \
    [10, 20] [40]
```

## B+树的特殊性

### B+树与B树的区别

1. **关键字存储**：B+树所有关键字都存储在叶子节点，内部节点只存索引
2. **叶子节点连接**：B+树叶子节点形成链表，支持范围查询
3. **查询效率**：B+树查询必须到叶子节点，查询效率稳定

### B+树插入

与B树类似，但分裂时中间关键字同时保留在原节点和上升到父节点：
```
分裂前：[10, 20, 30]

分裂后：
原节点：[10, 20]
新节点：[20, 30]
中间关键字20上升到父节点
```

## 时间复杂度

| 操作 | 时间复杂度 |
|------|-----------|
| 查找 | O(log_m n) |
| 插入 | O(log_m n) |
| 删除 | O(log_m n) |

## 关键要点

- B树的阶数m越大，树高度越低
- 插入可能导致节点分裂，从下向上传播
- 删除可能导致节点下溢，需要借关键字或合并
- B+树更适合范围查询，是数据库索引的首选
