# 排序算法对比：复杂度与稳定性

## 常见排序算法时间复杂度

| 算法 | 平均 | 最好 | 最坏 | 空间 | 稳定性 |
|------|------|------|------|------|--------|
| 冒泡排序 | O(n²) | O(n) | O(n²) | O(1) | 稳定 |
| 选择排序 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 |
| 插入排序 | O(n²) | O(n) | O(n²) | O(1) | 稳定 |
| 希尔排序 | O(n^1.3) | O(n) | O(n²) | O(1) | 不稳定 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 稳定 |
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n) | 不稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 |
| 计数排序 | O(n+k) | O(n+k) | O(n+k) | O(k) | 稳定 |
| 基数排序 | O(d·n) | O(d·n) | O(d·n) | O(n+k) | 稳定 |
| 桶排序 | O(n+k) | O(n+k) | O(n²) | O(n+k) | 稳定 |

## 稳定性的含义

稳定：相等的元素排序后相对顺序不变。比如按成绩排序，成绩相同的人保持原来的先后。

不稳定的根因：
- 选择排序：每次选最小值与当前位置交换，交换可能跳过相等元素
- 快速排序：partition 时相等元素可能被交换到对方前面
- 堆排序：建堆和调整过程中相等元素的相对位置被打乱

## 选型建议

- 数据量小（n < 50）或基本有序：插入排序（常数小、稳定）
- 通用场景、追求平均最快：快速排序（缓存友好、常数小）
- 要求稳定 + O(n log n)：归并排序（唯一稳定的 O(n log n) 原地不可，需 O(n) 空间）
- 要求原地 + O(n log n)：堆排序（不稳定但空间 O(1)）
- 数据范围有限的整数：计数排序 / 基数排序（线性时间）
- Java Arrays.sort：对象用 TimSort（归并+插入，稳定）；基本类型用双轴快排（不稳定但快）
- C++ std::sort：IntroSort（快排+堆排+插入，不稳定）；std::stable_sort：归并

## 面试高频问题

- 快排最坏 O(n²) 什么时候触发：每次 pivot 选到最大/最小值（如已排序数组取首元素），退化为 n 次 partition 每次只减少 1 个元素。解决：随机化 pivot / 三数取中
- 为什么快排平均比堆排快：快排的 partition 是顺序扫描（缓存友好），堆排的 sift 是随机跳跃（缓存不友好）；快排常数项更小
- 归并排序的 O(n) 空间能否优化：可以（手摇算法/原地归并），但常数极大，工程上不如直接用快排
- 哪些排序是稳定的：冒泡、插入、归并、计数、基数、桶（记忆口诀："冒插归计基桶"稳定）
- TimSort 为什么快：利用数据中已有的自然有序段（run），短 run 用插入排序扩展，长 run 用归并合并，实际数据接近 O(n)
