# 栈与队列对比及实现选型

## 栈（Stack）vs 队列（Queue）

| 维度 | 栈 | 队列 |
|------|-----|------|
| 操作原则 | 后进先出（LIFO） | 先进先出（FIFO） |
| 操作端 | 只在一端（栈顶）push/pop | 两端：队尾入队、队首出队 |
| 典型应用 | 函数调用栈、括号匹配、表达式求值、DFS、撤销操作 | BFS、任务调度、消息队列、缓冲区 |
| 时间复杂度 | push/pop 均 O(1) | enqueue/dequeue 均 O(1) |

## 数组实现 vs 链表实现

### 栈的实现对比

| 维度 | 数组栈 | 链表栈 |
|------|--------|--------|
| 空间 | 预分配固定大小（可能浪费）或动态扩容 | 按需分配，无浪费 |
| 扩容 | 满了需 realloc/resize（O(n) 均摊） | 无需扩容 |
| 缓存友好性 | 好（连续内存） | 差（指针跳跃） |
| 额外开销 | 无 | 每个节点多一个 next 指针 |
| 实现难度 | 极简 | 稍复杂（头插法） |

### 队列的实现对比

| 维度 | 数组队列（循环） | 链表队列 |
|------|------------------|----------|
| 空间 | 固定容量（循环数组） | 按需分配 |
| 假溢出 | 循环数组解决 | 不存在 |
| 缓存友好性 | 好 | 差 |
| 并发友好 | 需加锁或 CAS | 天然适合无锁（CAS head/tail） |
| 典型实现 | ArrayDeque、循环队列 | LinkedBlockingQueue |

## 选型建议

- 栈：绝大多数场景用数组栈（vector/ArrayList），缓存友好、实现简单。只在需要频繁中间插入/删除时才考虑链表。
- 队列：固定容量用循环数组（省内存、缓存友好）；容量不确定或多线程场景用链表（无锁并发队列通常基于链表）。
- 面试回答"数组实现栈和链表实现栈的优缺点"：数组栈缓存友好但有扩容开销；链表栈无扩容但每节点多一个指针、缓存不友好。实际工程中数组栈更常用。

## 面试高频问题

- 用栈实现队列：两个栈（输入栈 + 输出栈），均摊 O(1)
- 用队列实现栈：两个队列或一个队列（每次 push 后把前面的元素轮转到新元素后面）
- 单调栈：维护一个单调递增/递减的栈，用于"下一个更大元素""柱状图最大矩形"等问题
- 优先队列不是队列：底层是堆（完全二叉树），出队顺序由优先级决定而非入队顺序
