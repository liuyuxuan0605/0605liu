# BST 删除操作详解

## 核心原理

删除操作是BST中最复杂的操作，需根据被删除节点的子树情况分三种场景处理，同时保持BST的有序性。

## 删除的三种情况

### 情况1：叶子节点（左右子树均为空）

**处理方式**：直接删除该节点，将其父节点对应指针置为null。

**示例**：删除值为1的节点
```
    5                5
   / \              / \
  3   7    →       3   7
 / \ / \            \ / \
1  4 6  8           4 6  8
```

### 情况2：只有一个子树

**处理方式**：用子树替代被删除节点的位置（"提子上位"）。

**子情况2.1：只有左子树**
```
    5                5
   / \              / \
  3   7    →       2   7
 /   / \          /   / \
2   6   8        1   6   8
/
1
```

**子情况2.2：只有右子树**
```
    5                5
   / \              / \
  3   7    →       3   9
 /   /              \  /
1   9               4 8
    /
   8
```

### 情况3：左右子树均不为空

**处理方式**：找到中序后继（右子树最小节点）或中序前驱（左子树最大节点）替换当前节点值，再删除后继/前驱节点。

**示例**：删除值为5的节点（用后继6替换）
```
    5                6
   / \              / \
  3   7    →       3   7
 / \ / \            \   \
1  4 6  8            4   8
```

## 中序后继与前驱

- **中序后继**：右子树中最左侧节点（右子树最小值）
- **中序前驱**：左子树中最右侧节点（左子树最大值）

## 删除步骤总结

1. 定位待删除节点（类似查找操作）
2. 根据子树情况选择处理方式：
   - 无子节点 → 直接删除
   - 一个子节点 → 子节点上位
   - 两个子节点 → 后继/前驱替换后删除
3. 返回更新后的树

## 时间复杂度

- **平均情况**：O(log n)
- **最坏情况**：O(n) — 树退化时

## 关键要点

- 删除有两个子节点的节点时，后继节点必定是叶子或只有右子节点
- 前驱节点必定是叶子或只有左子节点
- 删除操作可能改变树的高度，这是平衡树需要重新平衡的原因
