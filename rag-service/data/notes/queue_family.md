# 队列家族：普通队列 / 循环队列 / 阻塞队列 分别解决什么问题

面试高频对比题。三者都是「先进先出（FIFO）」的变体，但各自解决不同痛点。

## 1. 普通队列（Queue）

- **解决什么**：最基础的 FIFO 顺序问题——生产者产生的元素按到达顺序被消费者处理（如任务调度、BFS）。
- **典型实现**：数组 + 头尾指针，或单链表。
- **痛点——假溢出**：数组实现时，出队只移动 `front` 指针，已出队空间无法复用；当 `rear` 到数组末尾但前面有空位时，仍会报「队满」，造成空间浪费。这就是普通队列的「假溢出」问题。

## 2. 循环队列（Circular Queue / Ring Buffer）

- **解决什么**：专门解决普通队列的**假溢出 / 空间浪费**。
- **做法**：逻辑上把数组首尾相接，用取模运算 `rear = (rear + 1) % capacity` 回绕。这样已出队释放的头部空间能被新入队元素复用，固定大小的环形缓冲可以一直循环使用。
- **满/空判定**：常用「牺牲一个槽位」`(rear + 1) % cap == front` 判满，或额外维护一个 `count` 计数器。`front == rear` 表示空。
- **适用**：有界缓冲、音频/网络包的环形缓冲（RingBuffer）、底层数据结构。

## 3. 阻塞队列（Blocking Queue）

- **解决什么**：解决**多线程并发下的同步与线程安全**——这是普通/循环队列都不管的。
- **做法**：在队列之上加锁 + 条件变量（Java 的 `wait()/notify()`、C 的 `pthread_cond_wait()/signal()`、Go 的 channel）。
  - 队列空时，消费者线程**等待**（释放锁、进入等待态），直到生产者放入元素后被唤醒；
  - 队列满时，生产者线程**等待**，直到消费者取走元素腾出空间后被唤醒。
- **价值**：把「手动加锁 + 忙等」变成了「自动阻塞/唤醒」，避免竞态条件与 CPU 空转。
- **适用**：线程池任务队列、生产者-消费者模型、任何跨线程传递数据的场景。

## 4. 双端队列（Deque）补充

- 两端都能进出的队列（常用双链表或带前后指针的动态数组实现），是栈和队列的泛化。很多「消息队列 / 任务队列」在单线程内可用 deque 实现。

## 5. 「实现一个消息队列应该用哪种数据结构」——选型建议

- **单线程 / 进程内**：普通队列或双端队列（deque）即可，追求两端操作可选 deque。
- **固定大小、高性能、底层缓冲**：环形队列（Ring Buffer），无锁场景也很常见。
- **多线程、需要线程安全**：阻塞队列（Blocking Queue）——它本就是为解决并发同步而设计。
- **分布式 / 持久化 / 高吞吐**：像 Kafka、RabbitMQ 这类「消息中间件」本质是「持久化的阻塞队列」变种（磁盘 + 顺序追加 + 消费者组），已超出内存数据结构范畴。
- 一句话：**要顺序用队列，要省空间用循环队列，要并发安全用阻塞队列，要跨线程通信首选阻塞队列。**
