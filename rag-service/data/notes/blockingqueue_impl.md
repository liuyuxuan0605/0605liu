# 阻塞队列（Blocking Queue）在多线程里是怎么等待和唤醒的

阻塞队列 = 普通队列（常为循环/数组队列）+ **锁 + 条件变量**，
让生产者在满时阻塞、消费者在空时阻塞，实现线程安全的"自动背压"。

## 核心组件
- 底层容器：循环数组 / 链表
- 一把互斥锁 `mutex`：保护队头队尾的并发修改
- 两个条件变量：`notEmpty`（队列非空，消费者等它）、`notFull`（队列非满，生产者等它）

## 入队 put(x)（生产者）
1. 加锁 `lock()`
2. `while` 队列满：`notFull.wait(lock)`  // 释放锁并休眠，直到被唤醒
3. 写入数据，`size++`
4. `notEmpty.notify()` / `notify_all()`  // 唤醒等数据的消费者
5. 解锁 `unlock()`

## 出队 take()（消费者）
1. 加锁 `lock()`
2. `while` 队列空：`notEmpty.wait(lock)`  // 休眠等生产者放入
3. 取出数据，`size--`
4. `notFull.notify()`  // 唤醒等空位的生产者
5. 解锁 `unlock()`

## 为什么用 `while` 而不是 `if`
`wait` 可能被**虚假唤醒**（spurious wakeup），或醒后发现又被别的线程抢先填满/取空，
所以用 `while` 循环重新检查条件，确保醒来时条件真的满足。

## 与环形缓冲、循环队列的关系
- 环形缓冲强调"固定数组 + 取模"的存储结构
- 阻塞队列在它之上加**并发等待/唤醒**语义，常用于线程池任务队列、生产者-消费者模型
