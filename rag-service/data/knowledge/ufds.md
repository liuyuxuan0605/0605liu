# UFDS 知识点（理论讲解，来源 VisuAlgo）

## 并查集（Union-Find Disjoint Sets, UFDS）

并查集（UFDS，英文 Union-Find Disjoint Sets）是一种用于建模若干「互不相交集合」的数据结构，它能够高效地（近似常数时间）完成三件事：判断某个元素属于哪个集合、判断两个元素是否在同一个集合、以及在需要时把两个不相交集合合并为一个。它可以用来求无向图的连通分量（Connected Components, CCs），因此也是 Kruskal 最小生成树（MST）算法的组成部分。注意这种数据结构还有一个别名：Disjoint Sets Union（DSU，即「并查集」的另一种叫法）。

## 可视化

在这里可以查看一个并查集示例的可视化！每棵树代表一个不相交集合（因此一组不相交集合构成森林），树的根节点就是该集合的「代表元」（representative item）。现在停下看看当前可视化的树：一共有多少个元素（N）？有几个不相交集合？每个集合的成员分别是什么？每个集合的代表元是哪个？

## 检查点 1

针对本电子讲义固定的默认示例，你的答案应该是：
N = 13，共有 4 个不相交集合：{0, 1, 2, 3, 4, 10}、{5, 7, 8, 11}、{6, 9}、{12}，其中带下划线的成员是各自集合的代表元。

## 数据存储 - 第一部分

我们可以用一个大小为 N 的数组 p 来记录这「森林」：p[i] 记录元素 i 的父节点；如果 p[i] = i，那么 i 就是这棵树的根，同时也是包含 i 的这个集合的代表元。
再次看上面的可视化，判断数组 p 里的值。
思考：如果 i 是它所在树的根，我们能不能改成用 p[i] = -1 而不是 p[i] = i？会有什么影响？

## 影响分析

把 p[i] = -1 也能工作，并且消除了「自环」的情况。我们只需要改代码去判断 p[i] = -1 而非 p[i] = i。具体用哪个版本由你决定。

## 检查点 2

在同一个固定示例上，你的答案应该是 p = [1, 3, 3, 3, 3, 5, 6, 5, 5, 6, 4, 8, 12]（大小为 N = 13，从 p[0] 到 p[12]）。
可以验证 p[3] = 3、p[5] = 5、p[6] = 6、p[12] = 12，这与 {3, 5, 6, 12} 是各集合代表元的事实一致。

## 数据存储 - 第二部分

我们还会用一个同样大小为 N 的数组 rank 记录额外信息。rank[i] 是以顶点 i 为根的子树高度的「上界」，它被用作 UnionSet(i, j) 操作的启发式指导。你会注意到，在「路径压缩（path compression）」启发式（稍后描述）压缩了某条路径之后，rank 值就不再反映该子树的真实高度了。
由于很多元素的 rank 为 0，为了界面简洁，VisuAlgo 只在某个顶点 i 的 rank 大于 0 时才在其下方显示 rank[i]（缩写为红色字符 r）。

## 检查点 3

在同一个固定示例上，验证 {1, 4, 6, 8} 的 rank 为 1，{3, 5} 的 rank 为 2，其余为 rank 0（不显示）。
此时所有 rank 值都是正确的，即它们确实描述了以该顶点为根的子树高度。接下来你会看到它们在后面的幻灯片里并不总是正确的。

## 操作

这个可视化页面提供五个 UFDS 操作：Examples、Initialize(N)、FindSet(i)、IsSameSet(i, j)、以及 UnionSet(i, j)。
第一个操作 Examples 是简单的：列出若干具有特殊性质的示例 UFDS 结构作为起点。本电子讲义始终使用「四个不相交集合」这个示例作为起点。
还要注意，没有任何示例包含「很高的树」。在我们描述完两个启发式之后你很快就会明白原因。

## Initialize(N, M)

Initialize(N, M)：创建 N 个元素，并用这 N 个元素组成 M 个不相交集合。我们随机挑选两个不相交集合并合并，直到剩下 M 个随机集合。由于使用了按秩合并（union-by-rank）启发式以及随机性，这个初始化过程几乎不会创建出很高的树。
默认形式是 Initialize(N, N)，即 M = N，所有 p[i] = i 且 rank[i] = 0（这些 rank 值初始都不显示）。该操作的时间复杂度显然是 O(N)。
受屏幕尺寸限制，我们设定 1 ≤ N ≤ 32，显然 M ≤ N。

## FindSet(i)（查找集合 / 找代表元）

FindSet(i)：从顶点 i 出发，沿树向上递归。即从顶点 i 走到 p[i]，一直到找到这棵树的根——也就是满足 p[i] = i 的代表元。
在 FindSet(i) 操作中，我们每次调用后都会采用「路径压缩（path compression）」启发式：路径上从 i 到根的每个顶点都会直接指向根（代表元），从而可以在 O(1) 内完成后续查找。

## 动手示例

如果执行 FindSet(12)，会立即得到顶点 12。
如果执行 FindSet(9)，经过 1 步得到顶点 6，结构无其他变化。
现在试试执行 FindSet(0)。如果这是你在默认示例上的第一次调用，它会经过 2 步返回顶点 3，然后由于路径压缩生效而修改底层 UFDS 结构（即顶点 0 直接指向顶点 3）。注意此时 rank[1] = 1 已经不对了，因为顶点 1 变成了新的叶子。但为了效率我们不会去更新它的值。
注意下一次再执行 FindSet(0) 时会（明显）更快，因为路径已经被压缩了。目前我们假设 FindSet(i) 运行在 O(1)。

## IsSameSet(i, j)（判断是否同集）

IsSameSet(i, j)：只需检查 FindSet(i) == FindSet(j) 是否成立。这个函数在 Kruskal 最小生成树（MST）算法中被大量使用。因为它只调用两次 FindSet，我们也假设它运行在 O(1)。
注意 FindSet 函数在 IsSameSet 内部被调用，因此路径压缩（path compression）启发式也被间接使用。

## 动手示例

如果调用 IsSameSet(3, 5)，应返回 false，因为顶点 3 和顶点 5 分别是各自集合的代表元且互不相同。
现在在默认示例上试试 IsSameSet(0, 11)，观察顶点 0 和顶点 11 上的间接路径压缩。应返回 false，因为两个代表元（顶点 3 和顶点 5）不同。注意顶点 {1, 5, 8} 的 rank 值现在不对了，但我们同样不会去修正它们——为了效率。

## UnionSet(i, j)（合并集合）

UnionSet(i, j)：如果元素 i 和 j 原本来自两个不相交集合，我们就把「较矮」的树/集合的代表元连接到「较高」的树/集合的代表元下面（否则什么都不做）。这也是在 O(1) 内完成的。
这就是「按秩合并（union-by-rank）」启发式在起作用，它使合并后的树相对矮。只有当两棵树在合并前高度相等时（通过比较它们的 rank 值来启发式判断——注意我们比较的是 rank 而非真实高度），合并后树的 rank 才会加 1。

## 间接路径压缩

还要注意，FindSet 函数在 UnionSet 内部被调用，所以路径压缩（path compression）启发式也被间接使用。每次路径压缩启发式压缩一条路径，至少有一个 rank 值会变得不正确。我们不会去修正这些 rank 值，因为它们只作为 UnionSet 函数的指导启发式。

## 动手示例

在默认示例上，试试 UnionSet(9, 12)。由于代表集合 {6, 9} 的树当前更高（依据 rank[6] = 1），那么代表集合 {12} 的较矮树会被挂到顶点 6 下面，完全不会增加合并后树的高度。
在同一个默认示例上，试试 UnionSet(0, 11)。注意顶点 3 和顶点 5 的 rank 相同，rank[3] = rank[5] = 2。因此我们可以把顶点 3 挂在顶点 5 下面（我们的实现），或把顶点 5 挂在顶点 3 下面（两者都会使合并后树的高度加 1）。注意这里间接的路径压缩（path compression）启发式在起作用。

测验：从 N = 8 个不相交集合开始，如果策略性地调用 7 次 UnionSet(i, j)，最终树最矮（按启发式）能有多矮？
排名选项：rank:2 / rank:3 / rank:5 / rank:1 / rank:4
提交
讨论：为什么？

## 答案

最高的树 rank 为 3（见 Tallest Tree）。要得到这种结构，需要用完全二叉树式的 UnionSet 策略，完全避免间接使用路径压缩（Path Compression）。我们依次调用：
最底层：UnionSet(0, 1)、UnionSet(2, 3)、UnionSet(4, 5)、UnionSet(6, 7)；
中间层：UnionSet(1, 3)、UnionSet(5, 7)；
最高层：UnionSet(3, 7)。
最矮的树 rank 为 1（见 Shortest Tree）。我们一直调用 UnionSet(x, 0)，∀x ∈ [1..7]。

## 真实时间复杂度

到目前为止我们都说 FindSet(i)、IsSameSet(i, j)、UnionSet(i, j) 运行在 O(1)。实际上，如果 UFDS 同时使用了路径压缩（path compression）和按秩合并（union-by-rank）两种启发式，它们运行在 O(α(N))，其中 α(N) 是反阿克曼函数（inverse Ackermann function），增长极其缓慢。在实际使用 UFDS（假设 N ≤ 1M）时，α(1M) ≈ 1。

## 合并、查找、能撤销合并吗？

注意并查集（UFDS）没有「撤销（undo）」操作。一旦两个原本不相交的集合被合并，就很难再把它们拆回原来的两个集合，尤其是当路径压缩已经把合并后的树压扁之后。
讨论：如果确实需要「撤销合并（de-Union）」「拆分（split）」或「剪切（cut）」操作，该怎么办？

## 答案

如果要做的是把一个原本连通的图逐个拆成多个连通分量，我们其实可以反向使用 UFDS（不从拆分入手，而是从最后一次操作倒着合并回第一次）。
对于更一般的动态图连通性问题（合并与撤销合并可以交错进行），可能需要另一种数据结构，例如 Link/cut Tree（链剖分树）。
