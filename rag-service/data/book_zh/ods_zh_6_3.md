# 6.3 讨论与练习

## 讨论与练习 (1/2)

二叉树已经被用来建模关系数千年了。一个原因是二叉树自然地建模（家
谱）家族树。这些家族树的根是一个人，左孩子和右孩子是这个人的父母
，如此递归下去。在近几个世纪，二叉树也被用来建模生物学中的物种树
，其中树的叶子代表现存物种，树的内部节点代表speciation events，在这
些节点中，单一物种的两个群体进化成两个不同的物种。
二叉搜索树似乎在20世纪50年代被几个小组独立发现 [48, 第6.2.2节]。
后续章节提供了对特定类型二叉搜索树的进一步参考。
在从零实现二叉树时，需要做出若干设计决策。其中一个问题是每个
节点是否存储指向其父节点的指针。如果大多数操作只是沿着从根到叶的
路径进行，那么父指针是没有必要的，会浪费空间，并且可能导致编码错
误。另一方面，如果没有父指针，则树的遍历必须通过递归或使用显式栈
来完成。一些其他方法（例如在某些类型的平衡二叉搜索树中插入或删除
）也会因为缺少父指针而变得复杂。
另一个设计决策涉及如何在节点处存储父节点、左子节点和右子节点
指针。在这里给出的实现中，这些指针作为单独的变量存储。另一种选择
是将它们存储在长度为 3 的数组 p 中，这样 u.p[0] 就是 u 的左子节点，u.p
[1] 是 u 的右子节点，u.p[2] 是 u 的父节点。以这种方式使用数组意味着某
些 if 语句序列可以简化为代数表达式。
这种简化的一个例子发生在树遍历过程中。如果遍历从 u.p[i] 到达节点
u，那么遍历中的下一个节点是 u.p[(i + 1) mod 3]。类似的例子也会出现在
存在左右对称的情况下。例如，u.p[i] 的兄弟节点是 u.p[(i + 1) mod 2]。这
个技巧无论 u.p[i] 是 u 的左孩子（i = 0）还是右孩子（i = 1）都适用。在
某些情况下，这意味着一些本来需要有左版本和右版本的复杂代码可以被
编写
仅执行一次十次。请参见第163页的 rotateLeft(u) 和 rotateRight(u) 方法作
为示例。
