# 10.3 讨论与练习

将完整二叉树以数组或列表的方式隐式表示，似乎最早是由 Eytzinger [27]
提出的。他在包含贵族家族族谱的书籍中使用了这种表示方式。这里描述
的二叉堆数据结构最早是由 Williams [78] 引入的。
这里描述的随机可合并堆（MeldableHeap）数据结构似乎最早是由 Ga
mbin 和 Malinowski 提出的 [34]。其他可合并堆的实现也存在，包括左倾
堆 [16, 48, 第5.3.2节]、二项堆 [75]、斐波那契堆 [30]、配对堆 [29] 和倾斜
堆 [72]，尽管这些都没有 MeldableHeap 结构那么简单。
上述一些结构也支持 decreaseKey(u, y) 操作，其中节点 u 中存储的值
被减小为 y。（前提条件是 y u. x。）在大多数前述结构中，这个操作可
≤
以通过删除节点 u 并添加 y 来在 O(log n) 时间内支持。然而，其中一些结
构可以更高效地实现 decreaseKey(u, y)。特别是，在斐波那契堆中 decrease
Key(u, y) 需要 O(1) 摊销时间，而在一种特殊版本的配对堆中则需要 O(log
log n) 摊销时间 [25]。这种更高效的 decreaseKey(u, y) 操作在加速多种图
算法中有应用，包括 Dijkstra 最短路径算法 [30]。

第11章
排序算法
本章讨论对一组 n 个项目进行排序的算法。这对于一本关于数据结构的书
来说可能显得有些奇怪，但这里有几个很好的理由将其包含进来。最明显
的原因是，其中的两种排序算法（快速排序和堆排序）与我们已经学习的
两种数据结构（分别是随机二叉搜索树和堆）密切相关。
本章的第一部分讨论了仅使用比较进行排序的算法，并介绍了三种运
行时间为 O(n log n) 的算法。事实证明，这三种算法在渐近意义上都是最
优的；任何仅使用比较的算法在最坏情况甚至平均情况下都无法避免进行
大约 n log n 次比较。
在继续之前，我们应该注意到，前几章中介绍的任何 SSet 或优先队列
实现也可以用于获得一个 O(n log n) 时间的排序算法。例如，我们可以通
过在二叉堆或可合并堆上执行 n 次 add(x) 操作，然后进行 n 次 remove()
操作来对 n 个元素进行排序。或者，我们可以在任何二叉搜索树数据结构
上执行 n 次 add(x) 操作，然后进行中序遍历（练习 6.8）以按排序顺序提
取元素。然而，在这两种情况下，我们都需要经历大量的开销来构建一个
从未完全使用的结构。排序是一个如此重要的问题，以至于值得开发尽可
能快速、简单和节省空间的直接方法。
